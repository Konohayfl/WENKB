# WenKB 测试计划说明书

版本：v0.1  
日期：2026-09-03  
阶段：测试计划  
范围：本文件基于需求分析、概要设计、详细设计、数据库设计、接口设计、操作流程与维护交接文档，描述目标产品的测试策略、测试范围、测试环境、测试数据、主要测试项、通过标准与风险控制，不依赖具体代码实现。

## 1. 文档目的

本文用于定义 WenKB 目标产品的测试目标与验证方法，为后续功能验证、回归测试、缺陷管理、发布验收和持续维护提供统一基线。

测试计划的重点不是描述当前仓库中已有实现，而是回答以下问题：

- 应该验证哪些目标产品能力。
- 应该如何组织测试层次与测试顺序。
- 应该在哪些环境和数据条件下执行测试。
- 哪些结果可以视为通过，哪些结果必须阻断交付。

## 2. 设计依据

本测试计划的依据如下：

- 需求分析说明书
- 概要设计说明书
- 详细设计说明书
- 数据库设计说明书
- 接口设计说明书
- 操作文档
- 代码维护交接记录

测试设计应以目标产品的业务边界为准，不应反向以某次实现细节替代需求和设计基线。

## 3. 测试目标

- 验证知识库导入、索引、检索、问答、引用和搜索等核心闭环是否满足目标产品预期。
- 验证模型配置、知识库设置、数据集状态与聊天记录等关键数据是否保持一致。
- 验证常见异常路径是否能返回明确提示并保留可追踪信息。
- 验证文档集、维护交接和接口约定等辅助能力是否与主流程保持一致。
- 验证目标产品文档本身是否形成可持续维护的测试基线。

## 4. 测试范围

### 4.1 必测范围

- 模型供应商、模型与默认模型选择。
- 知识库创建、编辑、删除与可见性控制。
- 数据集导入、启用、索引、重建与删除。
- 摘要、Q&A、三元组等知识增强能力。
- 聊天问答、重试、引用展示与消息留存。
- 搜索、历史记录与结果跳转。
- 文档集创建、编辑、版本与转入知识库。
- 数据库版本、迁移与基础一致性校验。
- 多用户注册、登录、JWT 认证、用户数据隔离及账号迁移。

### 4.2 重点回归范围

- 导入后状态流转是否正确。
- 索引失败后重试是否可恢复。
- 删除知识对象后关联数据是否同步清理。
- 问答返回是否保留引用快照。
- 维护文档与设计文档之间的内容一致性。

### 4.3 暂不作为本轮重点范围

- 大规模并发压测。
- 分布式部署与多租户隔离。
- 复杂团队协作流程。
- 非目标格式的多模态能力扩展。

## 5. 测试策略

- 分层验证：先做文档静态检查，再做关键功能验证，最后做回归与一致性核对。
- 风险优先：优先覆盖导入、索引、问答和删除链路，因为这些链路最容易引发数据不一致。
- 场景驱动：按用户实际操作路径组织测试，而不是按内部实现拆分测试。
- 独立可复现：每个测试项都应具备明确前置条件、操作步骤、预期结果和回滚方式。
- 版本可追溯：每次变更后都应补充或更新对应测试项，并记录结果。

## 6. 测试类型

### 6.1 静态文档测试

检查需求、设计、操作和测试文档之间的标题、术语、范围与约束是否一致。

### 6.2 功能测试

验证用户可见的主要操作是否符合目标产品预期，包括配置、导入、索引、问答、搜索和维护。

### 6.3 接口与流程测试

验证关键接口返回结构、状态流转、错误提示与流程衔接是否一致。

### 6.4 回归测试

在新增、修复或调整功能后，重新验证受影响的核心链路，避免旧问题复发。

### 6.5 数据一致性测试

验证关系数据、向量数据和文件数据在新增、修改、删除后的同步效果。

### 6.6 异常与恢复测试

验证文件解析失败、索引失败、模型不可用、任务中断等异常情况下的提示和恢复能力。

### 6.7 兼容性与可用性测试

验证目标产品在本地桌面与浏览器访问场景下的基本可用性，以及常见文件格式和内容长度下的表现。

## 7. 测试环境与准备

### 7.1 环境要求

- Windows 本地运行环境。
- 本地浏览器或桌面端入口。
- 关系型数据库环境。
- 向量检索环境。
- 可访问的模型服务或本地模型配置。
- 可读写的本地文件目录。

### 7.2 环境准备

- 初始化基础配置与默认数据。
- 准备至少一组可导入文档和一组可导入网页链接。
- 准备一组正常模型配置和一组异常模型配置。
- 准备一组可用于删除与重建的测试知识库。

### 7.3 环境检查

- 能正常启动目标产品。
- 能访问数据库与文件目录。
- 能完成基础健康检查。
- 能成功进入模型、知识库、数据集与聊天相关页面。

## 8. 测试数据与基线

### 8.1 基础测试数据

- 文档类：PDF、Word、Markdown、TXT、PPT 等代表性样本。
- 链接类：静态网页、有效链接、无效链接。
- 聊天类：单轮问题、多轮追问、重新生成问题。
- 搜索类：关键词、自然语言、无结果查询。

### 8.2 边界测试数据

- 空内容、超长标题、超长正文。
- 重复文件名、重复链接、重复导入。
- 不可解析文件、无法访问网页、无可用模型配置。
- 含特殊字符和中文路径的数据。

### 8.3 基线要求

- 每轮测试前应明确版本号和变更范围。
- 每轮测试后应记录通过项、失败项和回归项。
- 失败项应保留可复现输入，避免只记录现象不记录上下文。

## 9. 主要测试项

| 编号 | 测试项 | 关注点 | 预期结果 |
|---|---|---|---|
| TP-001 | 基础启动与健康检查 | 服务是否可启动，基础状态是否可见 | 能正常启动并返回明确状态 |
| TP-002 | 模型配置 | 供应商、模型、默认模型选择 | 配置可保存且可生效 |
| TP-003 | 知识库创建 | 名称、权限、索引模型 | 能创建并进入可维护状态 |
| TP-004 | 数据集导入 | 文档、链接、启用状态 | 导入后进入可索引状态 |
| TP-005 | 索引构建 | 主索引、失败回退、重试 | 索引结果可追踪可恢复 |
| TP-006 | 知识增强 | 摘要、Q&A、三元组 | 增强结果可查询可回归 |
| TP-007 | 聊天问答 | 多轮问答、流式输出、引用 | 回答可追溯且带引用 |
| TP-008 | 搜索能力 | 语义检索、结果展示、历史记录 | 可返回来源并支持追踪 |
| TP-009 | 文档集管理 | 文档、版本、转入知识库 | 版本清晰且可复用 |
| TP-010 | 删除与清理 | 关联对象、引用快照、索引同步 | 删除后无残留或脏引用 |
| TP-011 | 权限与可见性 | 私有/公开范围、列表收敛 | 仅显示可见对象 |
| TP-012 | 变更回归 | 新增修复后全链路回归 | 核心场景不回退 |

## 10. 缺陷管理与回归

- 缺陷应记录编号、版本、步骤、结果、期望值、影响范围和截图或日志。
- 高优先级缺陷应优先处理导入、索引、问答和删除链路。
- 修复完成后，应至少回归受影响测试项及其上游、下游相关项。
- 回归未通过时，不应以局部通过替代整体结论。

## 11. 通过标准

测试计划对应的交付条件如下：

- 核心功能测试项全部通过。
- 高优先级缺陷清零或已获得明确延期批准。
- 关键数据一致性检查通过。
- 设计文档、接口文档、操作文档与测试文档保持一致。
- 失败项均有可追踪记录和处理结论。

## 12. 风险与注意事项

- 模型服务不可用会放大问答、增强和索引相关测试的不稳定性。
- 文件解析质量可能受样本格式和内容完整性影响。
- 向量数据与关系数据之间存在最终一致窗口，测试时需区分瞬时状态和最终状态。
- 删除与重建相关测试应优先在可恢复的数据集上执行。
- 文档更新后应同步检查测试计划，避免测试基线滞后于设计变更。

## 13. 交付物与维护建议

- 测试计划文档。
- 测试用例清单。
- 测试执行记录。
- 缺陷清单与回归结果。
- 版本变更后的测试补充记录。

后续维护建议：

1. 随需求和设计文档演进同步更新测试范围。
2. 为高风险链路补充更细的场景化用例。
3. 在每次功能调整后补充对应回归项。
4. 将已验证的稳定场景沉淀为长期回归基线。

## 14. 验收标准

测试计划文档应满足：

- 能覆盖目标产品的核心功能和关键风险。
- 能描述明确的测试策略、环境、数据与通过标准。
- 能为后续测试执行与回归提供稳定基线。
- 不依赖具体代码实现即可独立阅读与评审。

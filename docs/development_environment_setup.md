# WenKB 开发环境搭建、开发者与用户手册

版本：v1.1<br>
日期：2026-10-24<br>
适用对象：首次搭建本地开发环境的开发者、课程演示、项目维护人员和普通用户

## 1. 目的与运行结构

本文说明如何在 Windows 本地准备 WenKB 开发环境、启动前后端、检查数据库初始化，并安全地处理登录账号和模型凭据。

WenKB 本地开发时由两个进程组成：Python/FastAPI 后端默认监听 `127.0.0.1:16088`，Vue/Vite 前端默认监听 `127.0.0.1:11420`。Vite 将 `/api`、`/static` 和 `/ws` 请求转发至后端。业务关系数据默认存储在 SQLite 文件 `wenkb-server/resources/database/wenkb.db`；上传文件、文档和向量索引保存在 `wenkb-server/resources` 下。

## 2. 需要准备的软件

| 软件 | 用途 | 版本或说明 |
|---|---|---|
| Git | 获取项目代码 | 使用当前受支持版本 |
| Python | 运行后端 | 项目服务端 README 指定 Python 3.11.5；建议使用 Python 3.11 系列 |
| Node.js 和 npm | 安装并运行前端 | 使用 Node.js LTS，并记录 `node --version`、`npm --version` 输出 |
| 浏览器 | 访问开发页面 | 使用近期版本的 Chrome、Edge 或 Firefox |
| Ollama（可选） | 在本机运行 Ollama 聊天模型 | 仅当选择 Ollama 作为聊天模型供应商时需要；也可配置可访问的远端供应商 |

默认数据库为 SQLite，无需单独安装或启动 MySQL、PostgreSQL 等数据库服务。项目包含本地 `m3e-small` embedding 模型资源；聊天模型需由用户在应用设置中配置，除非使用已准备好的本地 Ollama 服务。

## 3. 获取代码并安装依赖

在 PowerShell 中进入仓库目录。以下假设仓库已克隆到当前目录；若尚未获取代码，请先使用 Git 克隆项目并进入仓库根目录。

先检查软件版本：

```powershell
git --version
py -3.11 --version
node --version
npm --version
```

创建后端虚拟环境并安装依赖：

```powershell
cd wenkb-server
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

如果 PowerShell 阻止激活脚本，可不激活虚拟环境，直接使用虚拟环境解释器运行安装命令：

```powershell
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

依赖清单包含 PyTorch、模型处理组件和 `flash-attention`。Windows 上安装这些依赖可能受 Python、硬件和预编译 wheel 可用性影响；若安装失败，应先记录实际错误和适用的解决方式，不要跳过失败依赖后就认为环境已可用。

另开一个 PowerShell 窗口，回到仓库根目录安装前端依赖：

```powershell
cd wenkb-client
npm ci
```

`npm ci` 按 `package-lock.json` 安装依赖。若没有锁文件或需要有意更新依赖，才使用 `npm install`；不要在普通搭建过程中随意更新锁文件。

## 4. 数据库初始化与脚本

默认数据库是 SQLite，文件位置为 `wenkb-server/resources/database/wenkb.db`。项目随仓库提供 SQLite 基线文件。后端启动时会检查 schema 版本，并自动执行所需的 DDL/DML 升级脚本：

- 全新数据库基线脚本：`wenkb-server/server/db/upgrade/ddl/0.sql` 和 `dml/0.sql`。
- 后续版本升级脚本：对应目录中版本号高于当前数据库版本的 SQL 文件。
- 当前目标 schema 版本由 `wenkb-server/config/common.py` 中的 `DB_SCHEMA_VERSION` 指定。

正常本地启动不需要手动运行这些 SQL。不要把运行中的数据库文件覆盖为旧版本，也不要在升级失败后继续写入业务数据。若要手工验证迁移，应先备份数据库并使用副本；备份与恢复流程见[部署运维指南](deployment_guide.md)。

项目数据库基线不应包含演示者的真实账号或模型 API Key。提交数据库变更前，先检查并清理账号、密码哈希、模型凭据和其他个人数据。

## 5. 启动服务

### 5.1 启动后端

在一个 PowerShell 窗口中：

```powershell
cd wenkb-server
.\.venv\Scripts\python.exe app.py
```

后端启动后会运行数据库版本检查，并启动索引和增强任务队列。首次启动且未配置 `WENKB_JWT_SECRET` 时，会自动生成随机密钥并保存到 `wenkb-server/resources/jwt_secret.key`，后续启动会复用该文件。密钥文件已被 Git 忽略，不要提交、复制到公开材料或随意删除；更换密钥会使现有登录凭证失效。需要外部管理密钥时，可设置至少 32 字节的 `WENKB_JWT_SECRET`，但不要把实际值写入仓库文档。

健康检查地址：`http://127.0.0.1:16088/health`。确认返回健康状态后，再启动前端。

### 5.2 启动前端

在另一个 PowerShell 窗口中：

```powershell
cd wenkb-client
npm run dev
```

浏览器访问 `http://127.0.0.1:11420`。前端代理配置位于 `wenkb-client/vite.config.js`；若改动前后端端口，应同步检查代理配置。

## 6. 登录、密码和模型凭据

### 6.1 登录账号

项目没有预置登录账号或默认密码。首次运行时在登录页选择注册，使用自己的测试账号创建账户，再登录。注册密码长度要求为 8 至 128 个字符；服务端以 PBKDF2 哈希保存密码，不以明文保存。

开发环境文档和公开视频应只写“首次在登录页注册”，不要写个人密码或声称存在默认账号。录制时可使用专门的虚构演示账号，避免展示个人账户信息。

### 6.2 JWT 签名密钥

`WENKB_JWT_SECRET` 是服务端签发登录 token 使用的签名密钥，不是用户登录密码。默认情况下，服务会自动生成并复用 Git 忽略的本地文件 `wenkb-server/resources/jwt_secret.key`，开发者一般无需手工生成或提供该密钥。该密钥不得提交到 Git，也不应出现在截图、视频或公开文档中。

### 6.3 大模型 API Key

聊天和知识增强需要可用的聊天模型。登录 WenKB 后进入设置页，在模型供应商配置中填写 API Key、服务地址和模型信息，并选择默认聊天模型。API Key 属于敏感凭据：只在本地界面或本机安全配置中录入，不要写入 Markdown、源代码、Git、公开演示视频或截图。若演示需要展示配置步骤，应遮挡真实值并使用不可用的占位文本。

## 7. 首次运行验收

按以下顺序完成基础验收：

1. `http://127.0.0.1:16088/health` 返回健康状态。
2. `http://127.0.0.1:11420` 能正常打开登录页。
3. 能注册演示账号并登录。
4. 能打开模型设置页；若需验证聊天，则在本地配置可用的模型凭据。
5. 能打开知识库页面并创建或查看知识库。
6. 若要演示完整问答闭环，导入一个小型可解析文档，启用数据集并等待索引状态为 `ready`，然后提问并检查引用来源。

## 8. 常见问题

| 现象 | 检查方向 |
|---|---|
| 后端启动时报模块缺失 | 确认当前位于 `wenkb-server`，并使用该目录 `.venv` 中的 Python 安装 `requirements.txt` |
| `flash-attention` 或 PyTorch 安装失败 | 检查 Python 版本、Windows wheel 支持与依赖安装日志；按真实环境记录解决步骤 |
| 16088 或 11420 端口已占用 | 关闭占用该端口的进程，或在改端口后同步修改前端代理配置 |
| `/health` 无法访问 | 检查后端是否正常启动、端口是否正确、数据库目录是否可读写 |
| 登录 token 无效或反复回到登录页 | 检查 JWT 密钥文件是否可读写，以及不同后端实例是否使用同一个密钥；密钥变更后重新登录 |
| 登录成功但问答失败 | 检查默认聊天模型、供应商参数、API Key 和网络访问 |
| 导入资料后搜索不到 | 确认数据集已启用，且索引状态为 `ready` |

## 9. 开发验证命令

从仓库根目录运行项目测试：

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests
```

若修改后端代码，再执行编译检查：

```powershell
.venv\Scripts\python.exe -m compileall -q wenkb-server/server wenkb-server/app.py
```

前端测试和构建：

```powershell
cd wenkb-client
npm test
npm run build
```

## 10. 开发者手册

本部分面向开发与维护人员，补充项目运行形态、资源目录、后台任务、数据维护和开发排查。需求边界、数据模型、接口约定及部署策略仍以对应阶段文档为准。

### 10.1 项目运行形态

- 前端和后端默认在同一台电脑运行。
- 后端默认监听 `16088`，前端开发服务默认监听 `11420`。
- 业务关系数据默认保存在 SQLite；上传文件、文档和向量库默认落在 `wenkb-server/resources`。
- 索引及知识增强后台任务随服务进程运行。

当前形态适合个人知识库、课程实习、功能验证和本地二次开发。局域网部署涉及身份、权限、共享存储及任务调度，应先阅读[部署运维指南](deployment_guide.md)。

### 10.2 本地目录说明

| 目录或文件 | 作用 |
|---|---|
| `wenkb-server` | 后端服务、数据库迁移、模型资源和文件资源 |
| `wenkb-client` | 前端页面与桌面端工程 |
| `docs` | 软件工程阶段文档与维护文档 |
| `tests` | 文档、启动和维护回归测试 |
| `wenkb-server/resources/database/wenkb.db` | 默认 SQLite 数据库 |
| `wenkb-server/resources/static/upload` | 默认上传文件目录 |
| `wenkb-server/resources/documents` | 数据集文档资源目录 |
| `wenkb-server/resources/vector_store` | 向量库持久化目录 |

开发和运维时应重点保护数据库、上传文件、文档资源和向量库目录。备份与恢复步骤见[部署运维指南](deployment_guide.md)。

### 10.3 后台任务与数据集状态

主索引任务扫描已启用且待索引的数据集，将文档或网页内容切分后写入向量库；增强任务处理摘要、Q&A 和三元组，并调用模型生成结构化知识。

| 状态字段 | 常见值 | 含义 |
|---|---|---|
| `enbSts` | `enb` / `une` | 数据集是否启用 |
| `idxSts` | `new` / `order` / `index` / `ready` / `error` | 主索引状态 |
| `prcsSts` | `nobd` / `new` / `order` / `index` / `ready` / `error` | 摘要状态 |
| `qaSts` | `nobd` / `new` / `order` / `index` / `ready` / `error` | Q&A 状态 |
| `tpltSts` | `nobd` / `new` / `order` / `index` / `ready` / `error` | 三元组状态 |

排查索引问题时，先确认数据集已启用，再确认 `idxSts` 是否进入 `ready`，最后检查错误记录、文件可读性和后台任务日志。

### 10.4 数据与配置维护

- 数据库升级失败后不要继续写入业务数据；数据库与向量库不一致时，以数据库为准重建索引。
- 上传文件、文档资源和向量库均在本地持久化；移动项目目录后应确认资源路径可读写。
- API Key 等敏感参数应通过应用界面配置，不写入文档或代码。
- 默认 LLM 缺失时，聊天和知识增强无法正常工作。
- 已建立索引的知识库不应随意切换 embedding 模型；切换后应重建相关索引。
- 删除知识库或数据集后，应确认关联文件和向量数据已同步清理；备份频率和恢复流程见[部署运维指南](deployment_guide.md)。

### 10.5 开发验证与交付

每次变更后应运行项目测试；修改后端代码时还应执行编译检查。交付前确认测试通过、文档导航有效、维护交接记录已更新，并按仓库协作规则创建对应 Git commit。命令见[开发验证命令](#9-开发验证命令)。

### 10.6 开发者常见排查

**服务无法启动**：检查 `16088` 是否被占用、数据库目录是否可写、依赖是否完整，以及启动日志中的数据库迁移结果。

**登录凭证无效或已过期**：使用已注册账号重新登录；检查后端能否读写 `resources/jwt_secret.key`，以及多后端实例是否使用同一密钥。更换或删除密钥会使旧 token 失效。

**数据集一直不索引**：检查 `enbSts = enb`、`idxSts` 状态、后台任务日志及文件可读性。

**问答失败或检索效果差**：检查默认 LLM 和供应商参数、是否存在 `ready` 数据集、embedding 模型是否与现有索引一致，以及 `topK`、`smlrTrval` 和分段质量。

## 11. 用户手册

本部分面向普通用户，介绍模型配置、知识库和资料管理、问答、搜索及常见问题。首次使用前请先按本文前半部分启动前后端并注册账号。

### 11.1 首次使用

1. 启动 WenKB 并登录已注册账号。
2. 在设置页配置模型供应商并选择默认聊天模型。
3. 创建知识库并选择索引模型。
4. 导入文档或网页链接。
5. 启用数据集并等待索引完成。
6. 进入聊天页选择知识库并提问。

### 11.2 配置大模型

1. 打开“设置”并进入模型设置。
2. 选择需要使用的供应商。
3. 填写该供应商要求的参数，例如 API Key、服务地址和模型名称，然后保存。
4. 在模型首选项中选择默认 LLM 并保存。

默认 LLM 未设置或供应商参数不可用时，聊天和知识增强可能无法正常工作。不要将真实 API Key 提供给他人或写入项目文档。

### 11.3 创建知识库

1. 进入“知识库”页面并选择新建。
2. 填写知识库名称和介绍。
3. 选择索引模型并保存。

索引模型决定向量检索方式。已有索引后不建议随意更换 embedding 模型；确需切换时，应重建相关索引。

### 11.4 导入资料

**导入文档**：进入知识库详情的“数据集”页面，选择导入文档并上传 PDF、Word、Markdown、TXT、PPT 等资料。导入后启用数据集并等待索引完成。扫描版 PDF 可能无法正确解析，优先使用可复制文本的文档。

**导入网页**：选择导入网页链接，每行输入一个 URL 并保存，之后等待抓取和索引。无法访问或无法解析的网页会显示失败状态及错误原因，可修复后重新导入。

### 11.5 管理数据集

在知识库详情的数据集列表中，可启用或停用数据集、查看索引状态、重新构建索引、查看分段、维护摘要/Q&A/三元组，以及删除不再需要的数据集。`ready` 表示数据集已完成索引，可参与检索和问答。

### 11.6 知识库问答

1. 进入“聊天”页面并选择知识库。
2. 新建或选择一个对话。
3. 输入问题并发送，等待流式返回答案。
4. 查看答案下方的引用来源，核对回答依据。

若回答不理想，可补充资料、检查索引状态或调整知识库检索参数后重试。

### 11.7 搜索资料

进入“搜索”页面，输入关键词或自然语言问题，查看结果并跳转到对应知识库或数据集。搜索依赖已完成索引且已启用的数据集；没有结果时先确认索引状态。

### 11.8 使用文档集

文档集用于保存可编辑内容。用户可以创建文档集、新建或编辑文档、查看文档版本，并将文档内容转入知识库。转入后仍需等待数据集索引完成，才可参与问答和搜索。

### 11.9 用户常见问题

**问答没有结果**：确认已选择知识库、默认 LLM 已配置，并且知识库中有 `ready` 状态的数据集；也可补充更相关的资料或检查相似度阈值。

**导入后不能马上问答**：导入后还需要解析、切分和构建向量索引，索引完成前资料不会参与问答。

**引用为空**：数据集可能尚未索引完成，问题与资料相关度较低，或相似度阈值设置过高。

**模型无法回答**：检查 API Key、模型服务地址、默认 LLM 和网络连接。如果日志提示 Git LFS 占位权重或缺少 Git LFS，请安装 Git LFS 并按项目资源说明获取完整模型；如遇 OpenAI 兼容客户端的 `proxies` 参数错误，请确认依赖与项目版本一致并重启后端。

### 11.10 用户使用建议

- 一个知识库尽量围绕一个主题组织资料。
- 导入后先确认数据集启用且索引完成，再开始问答。
- 长文档可先查看分段质量，再判断回答效果。
- 使用引用来源核验关键答案。
- 定期清理无效或重复资料，保持知识库质量。

后续如新增部署方式、用户角色、权限控制、模型供应商、文件类型或局域网访问能力，应同步更新本手册并补充对应测试计划和维护交接记录。

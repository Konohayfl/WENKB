# WenKB 详细设计说明书

版本：v0.1  
日期：2026-09-02  
阶段：详细设计  
范围：本文件基于需求分析与概要设计，进一步细化核心对象、处理流程、状态流转、接口边界与一致性规则，作为后续编码实现的直接依据。

## 1. 设计目标

WenKB 的详细设计目标是把“知识导入 - 索引构建 - 结构化增强 - 检索问答 - 引用回溯”的目标产品能力，分解为可实现、可测试、可维护的模块级方案。

## 2. 设计依据

- 需求分析说明书
- 概要设计说明书
- 当前框架中已形成的产品形态和业务范围

本文件不绑定具体代码文件，但会沿用当前框架下的模块命名和业务划分方式，确保后续实现与现有基础一致。

## 3. 设计约定

- 所有 ID 均采用稳定唯一标识。
- 所有需要保留历史记录的对象都应带创建时间与创建人。
- 模型配置、知识库配置、数据集状态、聊天消息均可审计追踪。
- 主索引与增强索引分离处理。
- 数据库内容与向量库内容必须保持同步。
- 问答与增强流程均应支持流式或分步返回。

## 4. 逻辑架构

### 4.1 表现层

表现层负责页面、表单、列表、弹窗、消息流和状态展示。按业务可拆分为：

- 模型设置
- 知识库管理
- 数据集管理
- 聊天问答
- 全局搜索
- 文档集管理
- 应用编排

### 4.2 应用编排层

应用编排层负责把页面动作组织成完整业务用例，例如：

- 创建知识库
- 导入文档
- 导入网页链接
- 构建索引
- 启动增强任务
- 发起知识库问答
- 重新生成答案

### 4.3 领域服务层

领域服务层承载核心业务规则，包括：

- 模型参数解析
- 知识库设置读取
- 数据集导入与状态机控制
- 文本切分与索引同步
- 检索增强生成
- 引用生成与保存

### 4.4 基础设施层

基础设施层提供：

- 关系型数据库读写
- 本地文件系统访问
- 向量库访问
- LLM 调用适配
- 日志记录
- 后台任务调度

### 4.5 账号与认证模块

- 注册接口校验账号、昵称、密码及确认密码；账号按去除首尾空白并大小写折叠后的值唯一。
- 服务端解密现有前端 AES 请求载荷后，以 PBKDF2-HMAC-SHA256、独立随机盐保存密码哈希；不得保存或返回明文密码。
- 登录使用恒时比较验证密码，仅对启用账号签发 7 天 HS256 JWT；签发密钥通过 `WENKB_JWT_SECRET` 配置。
- `/sys/auth/login` 与 `/sys/auth/regist` 为公开 POST 接口；其余业务 API 和 WebSocket 必须从有效 JWT 读取用户 ID。
- 数据库升级版本 6 新建用户表；用户账号数据随应用数据库备份迁移，不写入代码仓库迁移脚本。

## 5. 核心数据对象

### 5.1 账号对象

- `userId`：服务端生成的稳定用户 ID。
- `username`：规范化后的唯一登录账号。
- `nickname`：展示名称。
- `passwordHash`：PBKDF2 慢速哈希及随机盐编码。
- `status`：账号启用状态。
- `crtTm`：注册时间。

密码明文只在单次请求内存中参与校验；JWT 仅承载用户 ID 与展示名称，不承载密码或敏感账号信息。

### 5.2 模型对象

#### 5.2.1 模型供应商

字段建议：

- `providerId`
- `providerName`
- `providerDesc`
- `providerIcon`
- `supportedTypes`

设计规则：

- 供应商用于描述一类模型接入能力。
- 同一供应商可提供多个模型。
- 供应商参数可按用户级或系统级保存。

#### 5.2.2 模型

字段建议：

- `modelId`
- `providerId`
- `modelName`
- `modelType`
- `modelIcon`
- `builtIn`
- `ownerUserId`

设计规则：

- 模型必须归属于某个供应商。
- 模型需区分是否内置与是否用户自定义。
- 模型类型至少包含 `llm` 与 `text-embedding`。

#### 5.2.3 模型参数

字段建议：

- `paramId`
- `providerId`
- `modelId`
- `userId`
- `paramCode`
- `paramValue`
- `encrypted`

设计规则：

- 回显时采用脱敏展示。
- 同名参数在不同层级按覆盖规则生效。

#### 5.2.4 模型首选项

字段建议：

设计规则：

- 首选项按用户保存。
- 问答默认使用 LLM 首选项。
- 向量构建默认使用知识库绑定的 embedding 模型。

## 6. 关键流程设计

### 6.1 模型配置流程

1. 用户选择供应商。
2. 用户填写供应商参数。
3. 用户选择或新增模型。
4. 系统保存参数并建立默认偏好。
5. 问答与增强任务按偏好选取模型。

设计要点：

- 配置变更应尽量即时生效。
- 参数保存应支持加密字段回显。

### 6.2 知识库创建流程

1. 用户填写知识库名称与描述。
2. 用户选择 embedding 模型。
3. 用户保存知识库。
4. 系统生成知识库标识和默认设置。

设计要点：

- embedding 模型一旦用于索引，应保持稳定。
- 知识库设置默认项应可初始化。

### 6.3 文档导入与索引流程

1. 用户上传文档或输入网页链接。
2. 系统记录原始资料元数据。
3. 系统将数据集置为待索引。
4. 后台任务扫描待索引数据集。
5. 系统解析内容并切分。
6. 系统写入分段与向量索引。
7. 系统更新索引状态。

设计要点：

- 主索引构建应异步化。
- 切分器应按文件类型选择。
- 失败时保留错误记录。

### 6.4 增强生成流程

1. 主索引完成后，用户触发摘要、Q&A 或三元组构建。
2. 后台任务读取分段内容。
3. 系统调用模型生成结构化结果。
4. 系统保存结构化结果并同步写入向量库。

设计要点：

- 增强任务共享调度机制，但按类型分别记录状态。
- 自动生成内容应允许后续人工修订。

### 6.5 问答流程

1. 用户选择知识库并创建对话。
2. 用户输入问题。
3. 系统获取知识库设置和模型首选项。
4. 系统进行相关内容检索。
5. 系统组织提示词。
6. 系统流式生成回答。
7. 系统返回答案和引用。

设计要点：

- 支持多轮对话历史。
- 支持重新生成。
- 支持来源展示与追问。

### 6.6 搜索流程

1. 用户输入查询条件。
2. 系统在向量库中检索相关资料。
3. 系统返回来源与片段。

设计要点：

- 搜索可复用问答前置检索。
- 搜索历史应可保存或删除。

## 7. 状态机设计

### 7.1 数据集主状态

| 状态 | 含义 | 进入条件 | 退出条件 |
|---|---|---|---|
| new | 待索引 | 新导入或重建后 | 入队 |
| order | 已排队 | 被后台扫描到 | 开始执行 |
| index | 索引中 | 任务开始 | 成功/失败 |
| ready | 已完成 | 索引成功 | 重新构建 |
| error | 索引失败 | 执行异常 | 用户修复后重试 |

### 7.2 增强状态

增强状态与主状态一致，但按类型分别维护：

- summary
- q&a
- triplet

### 7.3 对话状态

| 状态 | 含义 |
|---|---|
| active | 正常对话 |
| deleted | 已删除 |

## 8. 一致性与事务规则

- 新建知识库、数据集、对话等基础对象应在单事务内完成主要持久化。
- 主索引写入数据库与向量库时应保证先后顺序可回滚或可重试。
- 数据集删除时应同步删除分段、增强内容和向量索引。
- 分段、摘要、Q&A、三元组修改后应同步更新向量库内容。
- 知识库 embedding 模型与历史索引不一致时应提示重建。

## 9. 异常处理设计

### 9.1 模型异常

- 模型未配置
- 模型不可用
- 参数缺失
- 远程服务超时

处理原则：

- 返回明确错误信息。
- 保留失败上下文。

### 9.2 文档解析异常

- 文件格式不支持
- 文件读取失败
- 网页抓取失败
- 切分结果为空

处理原则：

- 数据集状态置为失败。
- 错误信息写入索引错误对象。

### 9.3 向量库异常

- 向量库初始化失败
- 写入失败
- 删除失败
- 检索失败

处理原则：

- 任务不中断主服务。
- 记录可追踪的错误信息。

## 1. 文档目的

本文从软件工程需求分析阶段出发，梳理 WenKB 目标产品的业务边界、目标用户、业务流程、功能需求、非功能需求、验收标准与后续演进方向。后续概要设计、详细设计、测试计划、部署运维文档应以本文为需求基准之一。

## 2. 参考对象

### 腾讯 IMA 参考点

腾讯 IMA 的公开定位是“以知识库为基础的 AI 知识管家”，提供知识库、问答历史、发现广场和客户端入口。其搜索结果摘要中还体现了“搜-读-写”一站式体验，以及文件、网页、图片、音频等多格式知识导入能力。

对 WenKB 的启发：

- 将产品定位从“个人知识库”扩展为“面向个人与小团队的 AI 知识工作台”。
- 将核心体验归纳为“导入、整理、检索、问答、生成、沉淀”。
- 强化知识来源管理、引用溯源、跨资料综合问答和写作辅助能力。
- 保留本项目当前的本地化、可接入多模型、可私有部署优势。

参考来源：

- [腾讯 IMA 官网](https://ima.qq.com/)
- [腾讯 IMA 官网搜索摘要：多格式导入、搜读写一站式体验](https://ima.qq.com/)

## 3. 产品定位

WenKB 是一款面向个人学习、研发文档管理、团队知识沉淀和私有知识问答场景的 AI 知识工作台。它通过大语言模型和向量检索技术，将本地文档、网页链接、结构化问答、摘要与知识图谱统一管理，并支持基于知识库的可追溯问答。

### 3.1 产品目标

- 让用户可以快速导入多来源资料并形成可检索知识库。
- 让用户可以用自然语言向指定知识库提问，并获得带引用的答案。
- 让用户可以自由选择云端或本地大模型，降低模型供应商绑定。
- 让用户可以沉淀摘要、Q&A、三元组等结构化知识。
- 让后续开发具备清晰、可追踪、可验收的需求基线。

### 3.2 产品边界

本阶段需求聚焦知识库核心闭环：

- 模型接入
- 知识库管理
- 资料导入
- 索引构建
- 知识增强
- 语义检索
- 知识库问答
- 引用溯源
- 基础配置与运维

暂不作为本阶段强制范围：

- 企业级权限体系
- 多租户 SaaS 计费
- 大规模分布式向量检索
- 在线协同编辑
- 移动端同步
- 公开知识库广场

## 4. 用户角色

### 4.1 个人用户

典型场景：课程资料整理、论文阅读、读书笔记、项目资料检索。

核心诉求：

- 快速导入资料
- 用问题找答案
- 查看答案依据
- 用本地模型或自有 API Key

### 4.2 知识库维护者

典型场景：维护项目文档库、产品手册库、研发规范库。

核心诉求：

- 管理知识库和数据集
- 查看索引构建状态
- 修正分段、摘要和 Q&A
- 控制知识库问答参数

### 4.3 开发与运维人员

典型场景：本地部署、二次开发、模型替换、问题排查。

核心诉求：

- 清楚系统运行链路
- 明确模型和向量库配置
- 便于定位索引、问答、文件解析错误
- 保持文档与代码演进一致

## 5. 业务流程

### 5.1 首次使用流程

1. 启动后端服务。
2. 启动前端页面或桌面端。
3. 进入模型设置页。
4. 配置模型供应商参数。
5. 选择默认 LLM。
6. 创建知识库并选择 embedding 模型。
7. 导入文档或网页链接。
8. 启用数据集并等待索引构建完成。
9. 进入聊天页选择知识库进行问答。

### 5.2 知识库构建流程

1. 用户创建知识库。
2. 用户选择 embedding 模型。
3. 用户导入数据集。
4. 系统保存文件或链接记录。
5. 系统后台扫描 `new + enb` 状态的数据集。
6. 系统解析内容并切分文本片段。
7. 系统写入分段表与 Chroma 向量库。
8. 数据集状态更新为 `ready` 或 `error`。

### 5.3 知识库问答流程

1. 用户在聊天页选择知识库。
2. 用户创建或选择对话。
3. 用户输入问题。
4. 系统根据知识库设置读取 `topK`、`maxCtx`、`smlrTrval`、`maxHist`。
5. 系统使用向量库检索相关片段。
6. 系统组装提示词并调用当前用户首选 LLM。
7. 系统流式返回答案。
8. 系统返回引用来源。
9. 用户可继续追问或重新生成答案。

### 5.4 知识增强流程

1. 数据集主索引达到 `ready`。
2. 用户在数据集列表点击摘要、Q&A 或图谱状态。
3. 系统将对应状态改为 `new`。
4. 后台增强任务扫描并入队。
5. 系统调用 LLM 生成摘要、问答对或三元组。
6. 系统保存结构化结果并同步写入向量库。

## 6. 功能需求

### FR-001 模型供应商管理

优先级：高

系统应支持查看内置模型供应商列表，包括 OpenAI、DeepSeek、Moonshot、Ollama、通义、智谱、WenKB 默认 embedding 等。

验收标准：

- 用户可以查看已设置和未设置供应商。
- 用户可以保存供应商级参数。
- 敏感参数如 `api_key` 应加密保存，回显时脱敏。

### FR-002 模型管理

优先级：高

系统应支持用户为供应商添加模型，并区分模型类型，例如 `llm`、`text-embedding`、`tts`。

验收标准：

- 用户可以添加供应商支持的模型名称。
- 用户可以为模型维护模型级参数。
- 聊天模型和 embedding 模型在选择器中应按类型过滤。

### FR-003 模型首选项

优先级：高

系统应支持用户选择默认 LLM，作为聊天、增强索引、摘要生成等能力的默认模型。

验收标准：

- 未配置默认 LLM 时，问答流程应给出明确提示。
- 配置默认 LLM 后，聊天请求应使用该模型。

### FR-004 知识库管理

优先级：高

系统应支持知识库的新建、编辑、删除、查看详情。

验收标准：

- 创建知识库必须填写名称并选择索引模型。
- 新建知识库默认私有。
- 已构建索引的知识库不建议随意切换 embedding 模型，界面或文档应给出提示。

### FR-005 知识库问答参数配置

优先级：高

系统应支持配置每个知识库的问答参数，包括最大上下文片段、聊天历史记录、温度、相似度阈值、TopK。

验收标准：

- 配置保存后应影响后续问答。
- 参数缺失时应使用合理默认值。
- 参数范围应在前端限制并在后端保持可校验。

### FR-006 数据集目录管理

优先级：中

系统应支持为知识库维护数据集目录，方便资料归档。

验收标准：

- 用户可以新增、编辑、删除目录。
- 删除目录不应删除数据集本身，数据集应回到未分类状态。
- 目录可排序。

### FR-007 文档导入

优先级：高

系统应支持上传常见文档格式，包括 PDF、DOCX、TXT、PPT、PPTX、MD。

验收标准：

- 用户可以批量上传文档。
- 系统保存原始文件与数据集记录。
- 上传后数据集进入待索引状态。
- 扫描版 PDF 暂不要求支持，但应提示用户。

### FR-008 网页链接导入

优先级：高

系统应支持导入静态网页地址，并尝试获取网页标题。

验收标准：

- 用户可以一次输入多个 URL。
- URL 格式应校验。
- 系统可以保存 URL、标题和数据集记录。
- 网页内容解析失败时应记录错误信息。

### FR-009 索引构建

优先级：高

系统应支持后台自动构建数据集向量索引。

验收标准：

- 仅启用状态的数据集进入索引队列。
- 索引状态至少包含 `new`、`order`、`index`、`ready`、`error`。
- 索引失败时应记录失败原因。
- 索引成功后可在问答流程中被检索。

### FR-010 分段管理

优先级：中

系统应支持查看、编辑、删除文档分段。

验收标准：

- 用户可分页查看分段内容。
- 修改分段后应同步更新向量库。
- 删除分段后应同步删除向量库记录。

### FR-011 摘要增强

优先级：中

系统应支持基于数据集分段生成摘要，并将摘要保存到数据库和向量库。

验收标准：

- 用户可手动触发摘要增强。
- 摘要生成状态可追踪。
- 摘要可查看、编辑、删除。

### FR-012 Q&A 增强

优先级：高

系统应支持自动生成数据集 Q&A，并支持人工新增、编辑、删除 Q&A。

验收标准：

- 自动 Q&A 与人工 Q&A 应区分来源。
- Q&A 应写入向量库，参与后续检索。
- 聊天输入时可展示候选问题。

### FR-013 知识图谱三元组

优先级：中

系统应支持从文档中抽取三元组，并以表格或图谱形式查看。

验收标准：

- 三元组包括主体、关系、客体。
- 三元组可新增、编辑、删除。
- 三元组应写入向量库。

### FR-014 知识库问答

优先级：高

系统应支持基于指定知识库进行多轮问答。

验收标准：

- 用户可以选择知识库。
- 用户可以新建对话。
- 回答应流式输出。
- 回答完成后应展示引用来源。
- 支持重新生成答案。

### FR-015 引用溯源

优先级：高

系统应在知识库问答中返回引用来源，帮助用户判断答案可信度。

验收标准：

- 引用信息至少包含数据集 ID、数据集名称、文件名、文件类型、相似度、片段内容。
- 用户能从回答中查看相关来源。

### FR-016 全局搜索

优先级：中

系统应支持对知识库资料进行搜索，优先使用向量语义搜索，必要时补充关键词过滤。

验收标准：

- 用户可输入关键词或自然语言。
- 搜索结果应包含来源信息。
- 搜索结果应可跳转到对应知识库或数据集详情。

### FR-017 文档集管理

优先级：中

系统应支持文档集、文档编辑、版本内容与文档转数据集能力。

验收标准：

- 用户可维护 Markdown 或富文本内容。
- 文档内容可转为知识库数据集。
- 文档版本应可追溯。

### FR-018 应用编排

优先级：低

系统当前已有应用信息与流程节点页面。后续可将其演进为基于知识库、LLM、分类节点和提示词节点的轻量 Agent 编排能力。

验收标准：

- 支持可视化节点配置。
- 支持输入变量、知识库选择、模型选择、提示词配置。
- 支持调试运行并查看中间结果。

## 7. 非功能需求

### NFR-001 可用性

- 首次启动失败时应给出明确错误信息。
- 文档导入、索引构建、问答生成应展示状态。
- 关键操作应有错误提示和恢复建议。

### NFR-002 性能

- 普通文档导入后应异步构建索引，避免阻塞界面。
- 向量写入应支持批量处理。
- 问答响应应采用流式输出，降低等待感。

### NFR-003 可靠性

- 后台任务失败时不得导致后端整体退出。
- 索引失败信息应可查询。
- 应避免因相对路径导致服务启动失败。

### NFR-004 安全性

- API Key 等敏感参数必须加密存储。
- 前端回显敏感字段时必须脱敏。
- 后续如引入团队协作，应补充权限边界与访问控制。

### NFR-005 可维护性

- 需求、设计、测试、部署文档应持续维护。
- 核心流程变更必须更新对应文档。
- 模型调用、文件解析、向量库访问应保持模块边界清晰。

### NFR-006 可扩展性

- 新模型供应商应通过配置和模型参数扩展。
- 新文件格式应通过 loader 扩展。
- 后续可替换向量数据库实现。

### NFR-007 兼容性

- 前端应能在浏览器开发模式和 Tauri 桌面端运行。
- 后端应支持 Windows 本地路径。
- 本地模型和云端模型都应可接入。

## 8. 核心数据对象

### 8.1 模型相关

- 模型供应商：供应商 ID、名称、描述、图标、支持模型类型。
- 模型：模型 ID、模型名称、模型类型、所属供应商、是否内置。
- 模型参数：参数编码、参数值、是否加密、用户 ID、模型 ID。
- 模型首选项：用户默认 LLM 和 embedding 偏好。

### 8.2 知识库相关

- 知识库：名称、介绍、权限范围、创建人、embedding 模型。
- 知识库设置：上下文数量、历史数量、温度、相似度阈值、TopK。
- 数据集：名称、文件类型、文件路径、启用状态、索引状态、增强状态。
- 分段：分段内容、辅助内容、序号、所属数据集。
- 摘要：摘要内容、来源、所属数据集。
- Q&A：问题、答案、来源、所属知识库和数据集。
- 三元组：主体、关系、客体、来源、所属数据集。

### 8.3 聊天相关

- 对话：所属知识库、标题、创建人、最后更新时间。
- 消息：父消息、角色、内容、创建时间。
- 引用：消息 ID、数据集信息、相似度、片段内容。

## 10. 与当前实现的差距

### 10.1 建议补强

- 前端需要更明确展示后端连接状态。
- 文档上传后默认未启用，用户路径不够直观，可增加导入后启用提示。
- 模型首选项当前主要暴露 LLM，embedding 首选项在页面中被注释，可评估是否恢复。
- 增强索引触发方式依赖点击状态标签，建议改为显式操作入口。
- 后端缺少统一的健康检查接口，可新增 `/health`。
- 需求、设计、测试、部署文档此前不完整，需要逐步补齐。

### 10.2 可参考 IMA 的演进方向

- 增加“搜、读、写”统一工作台入口。
- 支持更多资料类型，如图片、音频、Excel。
- 支持多知识库联合问答。
- 支持标签视图、文件夹视图、知识来源筛选。
- 支持基于知识库的写作辅助。
- 支持知识库分享或轻量团队协作。

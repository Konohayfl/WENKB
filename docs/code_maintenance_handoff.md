## 2. 项目进度审查与追踪

本文档是项目维护进度、历史变更、遗留事项和验证状态的唯一记录源。`AGENTS.md` 只提供文档导航和通用协作规则，不再复制维护历史。每次开始维护、进行阶段评审或准备交付时，都应主动使用本文档进行核对。

### 2.1 审查顺序

1. 阅读“当前未完成事项”，确认本轮目标、优先级和遗留风险。
2. 阅读“已完成工作”和“维护记录”，确认已有结论、影响范围和关联证据，避免重复处理或遗漏后续动作。
3. 检查“当前工作区状态”，确认工作区中的修改属于当前任务且没有覆盖无关改动。
4. 执行“验证状态”中的必要命令；若结果变化，立即更新验证结果和遗留风险。
5. 维护结束时，将本轮变更、测试、审查结论、未完成事项和 Git commit 追加到本文档。

### 2.2 进度追踪要求

| 追踪内容 | 必须记录的信息 | 更新时机 |
|---|---|---|
| 已完成工作 | 目标、实现或文档结果、影响范围、验证依据 | 变更完成并验证后 |
| 未完成事项 | 风险等级、问题描述、下一步动作、阻塞原因 | 每次审查和状态变化时 |
| 工作区状态 | 文件清单、用户已有修改、当前提交边界 | 开始和结束维护时 |
| 验证状态 | 测试命令、结果、告警、未覆盖风险 | 每次验证后 |
| 维护记录 | 日期、变更内容、关联测试、Git commit | 每次变更交付时 |

### 2.3 交付前审查门禁

- 需求、设计、实现、测试和部署文档之间不存在已知未记录的矛盾。
- 本轮变更已经补充或更新相关测试，并记录实际验证结果。
- 未完成事项已经明确保留、关闭或转入下一轮，不能只停留在口头说明。
- 当前工作区状态与提交内容一致，且本轮改动已创建可追踪的 Git commit。

## 3. 已完成工作

### 3.1 系统能力

- 新增 `GET /health` 健康检查接口。
- 健康检查会验证数据库连接，并使用统一成功或失败响应结构。
- 已在 `wenkb-server/app.py` 注册健康检查接口。

### 3.2 聊天与引用

- 新增聊天消息引用 ORM、实体和 `t_knb_chat_quote` 表。
- 问答检索结果会保存为引用快照，包含数据集、文件、相似度、正文和来源对象标识。
- 聊天消息查询会附带引用列表。
- 删除消息、对话、知识库聊天或知识库时会清理关联引用。
- 接口设计文档已补充聊天引用字段和流式事件约定。

### 3.3 知识库

- 当前用户的知识库列表会包含本人知识库和公开知识库。
- 创建知识库时会校验 embedding 模型，并初始化默认问答设置。
- 创建知识库时拒绝空白名称并去除名称首尾空白。
- 已有索引的数据集禁止直接切换 embedding 模型。
- 删除知识库时会清理数据集、聊天、搜索历史、引用、知识增强对象、关系库设置、向量集合及知识库上传文件；向量或关系库删除失败时恢复暂存文件。

### 3.4 数据集与索引

- 删除数据集时会清理分段、摘要、Q&A、三元组、索引错误记录和文件。
- 手工维护的摘要、Q&A、三元组也会随数据集删除。
- 向量不存在时，分段、摘要和三元组仍会更新关系库。
- 索引成功或重试成功后会清理旧错误记录。
- 数据库升级脚本会按文件名排序执行，并使用上下文管理器关闭 SQL 文件。

### 3.5 文档集

- 当前用户的文档集列表会包含本人文档集和公开文档集。
- 删除文档集或文档时会级联清理文档版本。
- 修改文档内容时会自动保存版本快照。
- 文档转数据集前会校验知识库存在性和访问权限。

### 3.6 搜索和数据库版本

- 修复搜索结果元数据缺失时 `dtsetId` 可能未定义的问题。
- 搜索按知识库 TopK 和相似度阈值检索，只包含已启用且索引 ready 的数据集；结果点击可打开对应数据集详情。
- 数据库版本号已调整为 `5`。
- `ddl/0.sql`、`ddl/2.sql` 和 `ddl/5.sql` 已同步索引错误表的新主键结构与迁移脚本。

### 3.7 访问控制与失败回落

- HTTP 与 WebSocket 请求身份从 HS256 JWT 的 `inf.id` 读取，不再把所有请求映射到固定 `client_default_user`；HTTP 无效凭证返回 401，WebSocket 拒绝无效凭证，密钥通过至少 32 字节的 `WENKB_JWT_SECRET` 配置。
- 知识库私有列表与详情按身份隔离，公开库对非所有者返回 `visit` 且写操作拒绝。
- 知识库、数据集、文档集、聊天和搜索的写接口已补充访问权限校验。
- `ask_to_llm_stream` 在 LLM 初始化、历史生成、检索或流式生成异常时回落到兜底消息并持久化，失败消息可由历史接口重新读取。
- 新增对应的维护测试，覆盖数据库版本 5、迁移脚本和聊天失败回落。

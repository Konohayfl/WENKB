## 4. 暂停边界与后续计划

当前工作簿是测试设计与记录模板，不是测试执行结果或验收结论。继续使用前应完成以下事项：

1. 对照测试计划和需求、概要设计、详细设计、数据库、接口及操作文档，复核 48 条用例的步骤、预期结果、前置条件和需求映射；确认每项属于目标产品基线。
2. 完成四张工作表的视觉复核，检查封面元信息、打印区域、列宽、换行、分页、表格筛选和状态提示；确认公式、数据验证、条件格式和冻结窗格导出后仍在。
3. 在副本中改变代表性用例状态，验证汇总数量、通过率、空结果检查和交付判定会按预期变化；检查不适用及缺失结论路径。恢复后再保存正式待执行版本。
4. 确认“UI界面”页状态与“测试项目”页用例之间采用独立验收还是联动规则。目前页面映射状态是单独的静态状态，不参与“运行”页汇总。
5. 根据实际测试安排填写版本、环境、测试数据、测试者和证据；只有真实执行后才能填写通过、失败、阻塞或不适用结论。
6. 完成上述事项后，将目录名从 `in-progress` 调整为经确认的最终命名，更新维护记录、回归测试和 Git commit。

封面中的文档编号、密级、审批、生效日期等项目管理信息尚未确认。不要根据推测填入。

## 1. 文档目的

本文用于统一 WenKB 的部署、运行、巡检、备份、升级和回滚方法，帮助维护人员在本机、单机服务和后续局域网环境中保持一致的运维标准。

## 3. 当前部署策略

### 3.1 当前形态

WenKB 当前以本地单机部署为主，也可在单机上提供浏览器访问的本地服务能力。

当前策略的核心特征如下：

- 前端与后端默认运行在同一台机器上。
- 数据默认保存在项目工作目录下。
- 任务队列和索引流程依赖本机运行环境。
- 适合个人使用、学习场景和小范围验证。

### 3.2 当前数据落点

- 业务数据库：`resources/database/wenkb.db`
- 上传文件：`resources/static/upload`
- 文档资源：`resources/documents`
- 向量库数据：`resources/vector_store`

### 3.3 当前运行入口

- 后端默认监听端口：`16088`
- 健康检查接口：`/health`
- 前端可通过本机桌面端或本机浏览器访问

### 3.4 当前部署判断

当前实现更接近“本地优先、单机优先”的产品形态，而不是面向多人并发的中心化服务器部署。

## 4. 部署前提

- 具备可运行的 Python 环境或等价打包环境。
- 具备可读写的项目目录权限。
- 能访问模型服务或本地模型资源。
- 能创建并持久化数据库、文件和向量库目录。
- 若通过浏览器访问，需要保证本机端口可达。
- 配置 `WENKB_JWT_SECRET`，值至少为 32 字节，用于签发 WenKB HS256 登录凭证；不得提交到版本库。
- 若通过非本机网络访问，应部署 HTTPS；前端密码载荷加密不能替代传输层加密。

## 5. 启动与验收

### 5.1 启动前检查

- 检查数据库目录是否可写。
- 检查上传、文档和向量库目录是否存在。
- 检查模型服务是否可用，或本地模型资源是否完整。
- 检查端口未被占用。

### 5.2 启动步骤

1. 启动后端服务。
2. 等待数据库初始化和版本检查完成。
3. 启动前端桌面端或浏览器入口。
4. 打开知识库、模型和聊天页面进行冒烟检查。

### 5.3 验收步骤

- 访问 `/health`，确认数据库状态正常。
- 验证模型设置页可打开。
- 验证知识库列表可加载。
- 验证可创建或查看数据集。
- 验证聊天页可发送问题并返回结果。

## 6. 当前运维事项

### 6.1 日常巡检

- 检查服务是否存活。
- 检查 `/health` 是否正常返回。
- 检查索引队列和增强任务是否持续积压。
- 检查日志中是否存在数据库、文件解析或模型调用错误。

### 6.2 数据备份

- 定期备份 `resources/database/wenkb.db`。
- 定期备份 `resources/static/upload`。
- 定期备份 `resources/documents`。
- 定期备份 `resources/vector_store`。

### 6.3 配置维护

- 维护模型供应商参数和 API Key。
- 维护默认聊天模型和 embedding 模型。
- 修改知识库 embedding 模型前，先确认是否需要重建索引。

### 6.4 故障处理

- 数据库异常时先检查文件权限和版本迁移。
- 导入失败时先检查文件格式、解析器和上传目录。
- 问答失败时先检查模型配置、知识库索引和引用数据。
- 索引失败时先检查后台任务日志和错误记录。

### 6.5 例行清理

- 清理无效测试数据。
- 清理重复导入产生的脏记录。
- 清理长期不用的临时文件和日志。

## 7. 备份与恢复

### 7.1 备份内容

- SQLite 数据库文件
- 上传文件目录
- 文档目录
- 向量库目录
- 配置导出文件

### 7.2 恢复顺序

1. 恢复数据库文件。
2. 恢复上传与文档目录。
3. 恢复向量库目录。
4. 启动服务并检查版本一致性。
5. 执行健康检查和关键流程冒烟测试。

### 7.3 恢复注意事项

- 恢复后应优先确认数据库版本与脚本版本一致。
- 若向量库与数据库出现不一致，应以数据库为准重新构建索引。

## 8. 升级与回滚

### 8.1 升级原则

- 升级前先完整备份。
- 升级顺序应先数据库，再服务，再功能验证。
- 升级后必须执行健康检查和核心流程回归。

### 8.2 回滚原则

- 升级失败时，优先恢复数据库和文件备份。
- 若升级已改变索引结构，应将相关数据集重新入队或重建。
- 回滚后再次执行健康检查和冒烟测试。

## 9. 距离局域网部署所需要的改动

### 9.1 网络接入改动

- 将服务绑定从单机默认访问扩展为局域网可访问。
- 配置反向代理或端口映射。
- 明确前端访问地址和后端 API 地址。

### 9.2 身份与权限改动

- 后端请求身份已从固定默认用户切换为校验 HS256 JWT，并以凭证中的 `inf.id` 作为数据所有者；缺失、无效或过期凭证不得访问受保护 API。
- 知识库列表、详情和写操作按所有者隔离，公开知识库仅提供只读访问。
- 按知识库、文档集和文件资源逐步完善访问控制，并随接口扩展保持服务端授权校验。
- 当前版本提供数据库持久化的注册/登录接口。首次部署前应配置 `WENKB_JWT_SECRET` 并备份数据库；数据库 schema 版本 6 会新增 `t_sys_user` 用户表。不要将含真实用户账号或密码哈希的运行数据库提交到源码仓库。

### 9.3 存储改动

- 将本地文件目录改造为可配置路径。
- 为多人访问准备共享存储或集中存储。
- 评估 SQLite 是否继续作为主库，或切换到服务型数据库。

### 9.4 任务调度改动

- 避免多实例重复扫描同一批任务。
- 为后台任务增加单实例锁、分布式锁或调度协调机制。
- 明确索引和增强任务的幂等性。

### 9.5 配置与发布改动

- 将端口、数据库路径、模型地址、密钥等参数外置。
- 增加环境区分能力。
- 支持统一的部署脚本或服务注册方式。

### 9.6 可观测性改动

- 统一日志格式和日志落点。
- 增加更明确的启动、升级、失败和恢复日志。
- 增加更完整的健康检查、巡检和告警入口。

### 9.7 前端接入改动

- 若采用浏览器访问，应补充跨域与静态资源发布方式。
- 若保留桌面端，应区分桌面运行与局域网访问两种入口。

## 10. 风险与注意事项

- 当前单机策略下的文件型数据库不适合高并发共享写入。
- 任务队列依赖本机进程，若多实例同时运行容易产生重复处理。
- 目录备份若不完整，恢复后容易出现数据库与向量库不一致。
- 变更 embedding 模型后若不重建索引，问答效果会明显下降。

## 11. 验收标准

部署运维文档应满足：

- 能说明当前部署策略和数据落点。
- 能覆盖日常运维、备份、恢复、升级与回滚。
- 能明确局域网部署所需的主要改动。
- 能作为后续部署实施和运维交接的基线。
